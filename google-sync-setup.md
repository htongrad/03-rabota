# Синхронизация Google в панели 03 «Работа»

## Подключение с телефона

1. Открой [панель «Работа»](https://htongrad.github.io/03-rabota/) в том же Chrome, где настроено «Личное».
2. Если Google в панели 03 ещё не настроен, нажми **«Настроить синхронизацию»** в «Обзоре». Открой **«Настройки подключения»**, нажми **«Заполнить из „Личного“»** и **«Сохранить настройки»**. Поля можно заполнить вручную.
3. Нажми **«Синхронизировать»**. Если Google попросит войти, выбери свой прежний аккаунт и разреши доступ. При первом подключении выбери папку **«03 РАБОТА»**. Панель запомнит папку и продолжит отправку.
4. В «Обзоре» проверь статус Google. Подробности по копии и календарю находятся в «⋯ → Настройки Google». Копии сохраняются на Диске с датой и временем. События поступают в отдельный календарь **«03 РАБОТА»**, владельцем которого является подключённый аккаунт.

## Повседневная работа

Кнопка **«Синхронизировать»** отправляет рабочие данные на Диск и обновляет календарь. При каждом изменении сохраняется отдельный JSON-файл. Предыдущие копии остаются на Диске. Повторная отправка тех же записей использует актуальную копию, если она по-прежнему доступна в рабочей папке. В файле хранятся журналы, их история и события панели. Настройки подключения хранятся отдельно в браузере.

Открытая панель автоматически отправляет сохранённые изменения, пока действует доступ Google. Когда интернет возвращается, отправка возобновляется. Если доступ истёк или страница перезагрузилась, нажми **«Синхронизировать»**. В «⋯ → Настройки Google» видны состояние и время последней отправки для Диска и Календаря. Сбой одного сервиса оставляет доступной отправку в другой. Диск и Календарь получают одно состояние записей за проход. Правки, сделанные во время отправки, идут в следующий проход.

## Восстановление

На новом телефоне или после очистки браузера сохрани настройки того же Google-проекта. Затем открой **⋯ → Настройки Google → Восстановить последнюю копию**. При необходимости подтверди вход и выбери рабочую папку. Проверь состав копии и нажми **«Восстановить»**. Отсутствующие записи будут добавлены, а совпадающие сохранят текущую версию. Если последняя копия недоступна или повреждена, панель предложит предыдущую исправную и покажет её дату по Москве. JSON также можно скачать и восстановить через **⋯ → Копии данных**. При повреждении локальных записей нажми **«Скачать исходные данные»**, проверь файл в загрузках и подтверди восстановление из рабочей копии.

## Зеркало календаря

- День в обзоре, рабочие сроки и обычные события считаются по Москве (Europe/Moscow). Событие без указанного окончания длится один час.
- Рабочие действия со сроком отправляются на весь день. Панель указывает точку, описание и ответственного, если они заполнены.
- Сроки меняй и действия закрывай в исходных журналах. Закрытое действие убирается из зеркала, история остаётся в журнале. События, созданные напрямую в Google, остаются самостоятельными.

## Настройка Google Cloud

Для ручной настройки нужны Client ID веб-клиента OAuth, числовой номер проекта и API key для Google Picker из одного проекта. Авторизованный JavaScript origin — `https://htongrad.github.io`. Для ключа Picker используй ограничение по сайту `https://htongrad.github.io/*` и по API. Включи Drive API, Picker API и Calendar API. Для проекта в режиме Testing добавь свой аккаунт в Test users.

Панель запрашивает `openid`, `drive.file`, `calendar.events.owned` и `calendar.calendarlist.readonly`. Настройки могут быть общими с панелями 01 и 02. Токен хранится в памяти открытой страницы.

- [OAuth для браузера](https://developers.google.com/identity/oauth2/web/guides/use-token-model)
- [Google Picker](https://developers.google.com/drive/picker/guides/overview)
- [Разрешения Google Calendar API](https://developers.google.com/workspace/calendar/api/auth)
