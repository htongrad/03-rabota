В этом выпуске отправка и восстановление проверялись на имитации API. Рабочие события и документы пользователя в испытаниях не менялись.

Проверка приложения на тестовых данных пройдена. Для рабочего выпуска требуется проверка установленной панели на Android и восстановления и зеркала в рабочем аккаунте Google.

| Проверка | Что подтверждено |
|---|---|
| Сценарий пилотной точки | Импорт настроек, заполнение карточки точки, сверка допуска команды, смены, техкарты, партий и закупочных данных, старт пилота, решение, фактический ввод и подтверждение эффекта. Ввод разрешается на пилотной точке первой. |
| Управленческий цикл | Создание действия из исходного показателя, фиксация выполнения и проверка того же показателя за сопоставимый завершённый период. |
| Резервная копия | Экспорт всех связанных записей, восстановление в чистом и повторный импорт в заполненном хранилище. Совпадающие записи сохраняют текущие значения. |
| Календарь | На имитации Google API сроки фактических записей появляются в зеркале, повторная отправка не создаёт копий, закрытые этапы исчезают. |

| Инструкция | Уточнены формулы фудкоста и маржинальности, порядок приёмки ремонта и приоритет ограничений в «Обзоре». |

Пройдены 25 проверок отдельных модулей и сквозной сценарий на двух наборах настроек. В сквозном прогоне журналы содержат синтетические записи. Первичные данные и допуски подготовлены как тестовая исходная точка. Старт, решение, ввод, оценка, улучшение и восстановление выполнены через формы панели. Google API в тестах имитирован.

## Повторный прогон

Из корня репозитория на Node.js 22 или новее:

```sh
npm ci --prefix qa --ignore-scripts
npm test --prefix qa
```

По умолчанию используется полностью вымышленная сеть. Копию стартовых настроек можно передать локальным аргументом с абсолютным путём:

```sh
npm test --prefix qa -- /absolute/path/network-settings.json
```

Тест использует временное хранилище. Подготовка, прогон и восстановление не записывают данные в исходный файл настроек. Зависимости относятся к проверкам. Панель GitHub Pages запускается без сборки.

## План исходной предзапусковой приёмки

1. **Android.** Открыть точную сборку для приёмки в Chrome. Проверить нижние вкладки, ввод в длинной форме с открытой клавиатурой, установку и повторное открытие панели без сети.
2. **Копия Google.** На тестовой записи проверить отправку, затем восстановление на отдельном профиле браузера. Проверить отчёт восстановления, время копии и звенья записи. Использовать отдельную копию для приёмки при наличии рабочих данных.
3. **Календарь «03 РАБОТА».** Проверить появление тестового срока, перенос и снятие после закрытия. Сверить сохранность прямого события в Календаре.
4. **Решение о выпуске.** После подтверждения предыдущих пунктов согласовать публикацию рабочей ветки и отдельно начать работу с фактическими записями пилотной точки.
